Local Embeddings

ConstructLM's privacy-first architecture uses Transformers.js to generate embeddings entirely in your browser. Your documents never leave your device during the embedding process.

What Are Embeddings?

Embeddings are numerical representations of text that capture semantic meaning. They allow the system to understand which pieces of text are similar or related, even if they don't use the exact same words.

For example, these sentences have similar embeddings:

  • "How do I configure the API?"
  • "What are the API setup steps?"
  • "API configuration instructions"

Transformers.js

ConstructLM uses Transformers.js by Xenova, which brings state-of-the-art machine learning models to the browser using WebAssembly and ONNX Runtime.

Model: Xenova/all-MiniLM-L6-v2

  • Type: Sentence transformer
  • Size: ~25MB (downloaded once, cached forever)
  • Dimensions: 384-dimensional vectors
  • Speed: ~50-100 chunks per second (browser-dependent)
  • Quality: Excellent for semantic search and RAG applications

How It Works

  1. First-Time Setup

    When you upload your first document, the embedding model (~25MB) is downloaded from HuggingFace CDN and cached in your browser.

  2. Text Chunking

    Documents are split into chunks of 1000 characters with 200-character overlap to maintain context across boundaries.

  3. Local Embedding Generation

    Each chunk is processed through the model running in your browser via WebAssembly. This generates a 384-dimensional vector for each chunk.

  4. IndexedDB Storage

    Vectors are stored locally in IndexedDB along with the original text chunks. Nothing is sent to external servers.

  5. Query Embedding

    When you ask a question, it's embedded using the same local model to create a query vector.

  6. Similarity Search

    Cosine similarity is calculated between the query vector and all document chunk vectors to find the most relevant passages.

Privacy Benefits

100% Local Processing

Your documents are never sent to external servers for embedding. All processing happens in your browser using WebAssembly.

  • No Data Leakage: Documents stay on your device
  • No API Costs: Embedding is completely free
  • Offline Capable: Once model is cached, embeddings work offline
  • No Rate Limits: Process as many documents as you want
  • Instant Processing: No network latency for embedding

Technical Details

Chunking Strategy

Chunk Size: 1000 characters
Overlap: 200 characters
Strategy: Sliding window

Example:
Chunk 1: chars 0-1000
Chunk 2: chars 800-1800 (200 char overlap)
Chunk 3: chars 1600-2600 (200 char overlap)

Vector Similarity

Cosine similarity is used to compare vectors:

similarity = (A · B) / (||A|| × ||B||)

Where:
- A · B = dot product of vectors A and B
- ||A|| = magnitude of vector A
- ||B|| = magnitude of vector B

Result: Value between -1 and 1
- 1 = identical meaning
- 0 = unrelated
- -1 = opposite meaning

Relevance Threshold

ConstructLM uses a threshold of 0.15 for cosine similarity. Chunks below this threshold are considered irrelevant and excluded from results.

Limitations

  • Browser Performance: Slower than server-side embedding on older devices
  • Model Size: 25MB initial download required
  • Context Length: 512 tokens max per chunk (model limitation)
  • Language Support: Optimized for English, works with other languages but may be less accurate
  • Memory: Large document sets may consume significant RAM

Best Practices

  • First Upload: Be patient during initial model download
  • Batch Uploads: Upload multiple files at once for efficiency
  • Document Size: Break very large documents (>5MB) into smaller files
  • Clear Cache: If model seems corrupted, clear browser cache and re-download
  • Modern Browser: Use latest Chrome/Edge for best performance
